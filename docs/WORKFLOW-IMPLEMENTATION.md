## P01 checkpoint

Rules now use compact rows with always-visible scope/origin/switch and expandable details/actions. Search/status remain primary; additional filters are disclosed with a visible active-filter summary and reset. Rule/sample tabs share semantic theme tokens and explicit selected state. Rule dialogs use the application font, surfaces, borders and backdrop. Five short rules and switches fit 1280×900 without scrolling. Arabic RTL at 375 px and dark mode were inspected, as was the German desktop screenshot. Stable screenshots disable finite transitions to avoid capturing intermediate theme colors.

Canonical sample cards initially show an accurate derived pending/accepted count; proposals, evidence and history are loaded on explicit expansion. Pending proposal pagination stays in the sample. Legacy analysis details are disclosed while explicit editing remains available. Displayed language names/layout labels/numbers follow the interface locale. New generated rule titles carry optional validated `titleMode` provenance through encrypted persistence. Manual/Foli replacements remain custom; duplicate sample evidence cannot rename an existing custom rule. Old sample-only records are localized only when their exact title matches a known generated layout/field-order signature; custom/manual/chat titles remain untouched. No provider request is added.

Evidence: 21 focused rules/sample/Foli checks passed, including explicit-title replacement/duplicate protection, encrypted restart/backup and failed writes. Seven existing HTTP/learning cases passed, including approval atomicity, stale decisions, glossary and source removal. Rule/sample browser flows passed Chromium, Firefox and WebKit; the existing legacy profile-edit flow passed WebKit. Expanded rule flow verifies five visible desktop rows, generated German decimal formatting versus unchanged custom titles, keyboard tab state, scope retention and zero provider calls. A final Chromium sample flow verifies old generated titles without the new provenance field still display correctly.

The new sample summary made the old browser assertion “contains Accepted” insufficient because that label exists before approval; it now waits for the actual approved rule row before checking persisted state. The desktop fit check initially exposed inherited top margins and separate metadata lines; shared compact row styles remove those while preserving 44 px switches. The final requirement remains unchanged and passes. These checks do not stand in for P02–P10 or final package/upgrade/publication acceptance.

## P02 checkpoint

Foli now has a height-aware scrollable log and a separate composer. Empty-chat examples are hidden once a conversation has content; uncommon settings/delete actions use a native disclosure. Compact/typing layouts keep the composer reachable in short viewports, including the visual viewport. Returning from a changed size/locale follows the tail only when appropriate; reading earlier messages retains its position and a new-message action reveals later content. Upward wheel/touch and Home/End intent are handled before resize/scroll-follow callbacks so the browser cannot bounce a reader back to the tail.

Accepted/rejected proposals collapse into persisted-decision confirmations with optional effect/version details. Accepted confirmations explicitly describe the historical decision and link to the current saved rule by an exact bounded ID filter; unrelated library pages/filters cannot hide that target. Missing/deleted targets are explained. Proposal reads/rendering are ticketed against stale responses. Replacements whose target version changed (or was deleted) show a stale state with approval disabled; server version/atomicity checks remain authoritative, and users may still discard or explicitly adjust drafts. No new chat accounting display or model call is added.

Evidence: the expanded existing Foli browser flow uses ten additional fictional local exchanges, keeps a reader at the beginning while a new message appears, returns to the tail, checks a deliberately stale replacement cannot be approved, retains an unsent draft, and exercises 375×800/600/440 layouts plus EN/DE/AR. It passes Chromium, Firefox and WebKit across checkpoints; after the final input-intent fix, WebKit passes and the final Chromium Foli/rule/sample regression run passes 3/3. The Arabic mobile screenshot was inspected. Ten existing Foli/rule HTTP checks pass, including the exact ID filter, missing/oversized selections, CSRF/owner/budget behavior, duplicate request handling and persistence failure rollback. Only the original explicit mock reply/cancellation calls occur; local chat/rule navigation and all seeded exchanges make zero additional provider requests.

A cross-engine check exposed that a pending size-follow callback could interfere with native scroll initiation. Explicit upward intent plus consistent focused-log Home/End handling fixes the product interaction; the beginning/tail preservation assertions remain unchanged. Accepted confirmations after reload still read the persisted proposal result, not transient optimistic UI state. P03–P10 and full installed upgrade/release acceptance remain open.


## P03 checkpoint

Added a read-only, selected-version-bound local layout preview using the canonical context/resolver and the production PDF/Word exporters. The same bounded fictional multi-page table document is rendered before/after a single validated layout key; real job applicability and conflicts are shown separately. Saved rules and pending create/replace proposals can open the comparison; wording/terminology changes do not pretend to have locally generated linguistic examples. PDF.js renders the actual PDFs, with PDF and explicit Word downloads. Closing disposes PDF tasks and object URLs. Preview headers explicitly identify fictional examples. The UI explains possible PDF font substitution when Aptos is unavailable.

All seven layout effects are covered by focused derivation checks. Actual Word OOXML checks verify 1.0/1.5 line spacing, title alignment, table widths, margins, paragraph spacing, row splitting and page numbers. These checks exposed that the existing Word title ignored `titleAlign`; the shared exporter now applies it to its primary title, retaining the existing centered default. A rendered PDF comparison was inspected in the actual browser dialog. Full multi-page before/after inspection for row splitting and page numbering, mobile/RTL preview inspection and final integration remain pending.

Accepted active dependent rules now expose a separate confirmed source activation action both in the library and sample review, with the saved-rule/source-off distinction. The operation checks rule and source versions and never enables a disabled rule. A new optional synchronous source operation in the workspace write queue clones source metadata and publishes it only after the encrypted write succeeds. Focused HTTP checks prove stale rejection, separate approval, failed-save rollback and disabled-rule protection; the explicit activation browser flow refreshes the sample switch as well as its inner rules. Review interaction with already-queued ordinary workspace saves before calling this package complete; the existing ordinary save captures non-library metadata before entering the write queue.

Evidence so far: 10 unit/HTTP checks pass across focused runs (six existing/extended API cases and four preview cases). The expanded rule browser flow passes Chromium and WebKit with actual local PDF preview and zero provider calls. The existing sample browser flow passes WebKit; the final expanded explicit-activation sample flow passes Chromium. Earlier fixture expectations were corrected to the real stale error after approval increments the proposal version. The first activation implementation incorrectly expected source records in the rule-only transaction input; it was replaced by the source operation described above and failed-write checks now pass. These are development checkpoints, not a full P03 or release declaration.


P03 follow-up: source commits now carry an in-process generation so a previously queued ordinary save merges newer committed source versions instead of restoring an old activation state. Same-version conflicting edits fail explicitly; intentional removals/newer edits and restore behavior remain separate. A held durable-write test proves the activation is invisible before commit, survives a queued preference save and encrypted restart, and stays unchanged on a denied write. Replacement previews now use the actual pre-approval snapshot (for example 1.2 → 1.5), rather than dropping the old rule and accidentally illustrating the default. Legacy source states without a status remain eligible consistently with the existing switch.

Final focused checkpoint: 19 checks pass in the rules/API/preview set. The final Chromium rules and sample flows pass 2/2, including the Arabic 375 px preview, actual PDF canvases, independent source activation confirmation and refreshed outer sample switch. The mobile Arabic preview and actual multi-page keep-rows/page-number comparisons were visually inspected: disabling row cohesion visibly splits a row across pages; disabling page numbering removes the footer number on page 2. Word/PDF download links use localized labels. P03 is implemented with focused acceptance; broad repository, installed upgrade and publication gates remain open along with P04–P10.


## P04 checkpoint (in progress)

Source decisions now store a binding to exact original document/page identity, kind, available geometry, source text and (for mappings) the selected target nodes' semantic contents. Read/rebuild validation reopens changed or unbound decisions and marks them stale while retaining their historical decision; unrelated target edits keep their decisions. Validation does not mutate stored historical snapshots. Replacing original bytes cannot inherit decisions merely because extracted text/page coordinates happen to match. Target binding indexes are built once per inventory display pass. Existing extraction grouping metadata can evolve without invalidating an otherwise identical decision.

The existing source inventory UI gains a page overview with open counts and a page filter, preserving its existing bounded item pagination. Selecting a source block retains the original-page/available-box navigation and shows its linked translation from the current document model. Missing coordinates and stale decisions have explicit localized explanations; automatic mappings are not described as confirmed linguistic accuracy. Filtering preserves the full page overview across subsequent pager navigation. A guard fixes an archived job with no original previews producing an exception when a page is selected.

Evidence: 17 existing/extended source-inventory checks pass, including ambiguity, actual PDF text geometry and corrected scan transformations. The new binding case verifies JSON round-trip, affected versus unaffected target changes, non-mutating display validation and different original bytes. The extended archived-review Chromium flow proves page filtering/all-pages reset and missing-area copy without hydrating the complete archived record or external requests. P04 remains incomplete: inspect the genuine multi-page paragraph/table/stamp UI fixture, test source decisions across encrypted restart and subsequent revisions, and verify mobile/RTL plus extraction-limit visibility before marking its focused acceptance complete. P05–P10 and final integrated/package/release gates remain pending.
