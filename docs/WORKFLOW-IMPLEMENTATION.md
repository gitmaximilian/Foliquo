## P10 foundation checkpoint — not feature complete

Extracted the existing streaming backup JSON reader into `lib/json-file-reader.mjs`, preserving the restore path. Its shared scanner now skips large strings/containers by buffer rather than awaiting each byte. A bounded projection mode selects searchable current/history text and saved provenance without hydrating original/export binaries, chats or pending revisions. Inline JSON text ranges and authenticated UTF-8 secure objects are read inside the existing private decryption staging lifetime, with cancellation and cleanup.

JobStore now exposes a separate committed-only, owner-required search catalog. Deferred workspace writes remain invisible to this catalog until commit; rollback retains the old catalog. Search material checks owner, authenticated record digest, exact secure-object reference and source stamp, and discards a result if the source was replaced/deleted during consumption. Existing primary store/index schemas and the normal library summary DTO are unchanged. The initial search stamp conservatively uses the committed record digest; unrelated record saves may therefore invalidate a derived entry as well.

Added grapheme-based DE/EN/AR text folding with original UTF-16 highlight spans. Numeric graphemes retain their original glyphs: ASCII, Arabic-Indic and full-width numbers are not folded together. Numeric-only searches reject substrings inside longer numbers. Text is streamed into overlapping 64 Ki UTF-16 chunks, with a default 4 Mi-character work-step budget and resumable source offsets. Source byte authentication may be repeated when resuming a large object, but the whole translation is never retained by the chunker. Pathological combining sequences that exceed the safe chunk boundary are explicitly reported limited rather than silently split. Each chunk records whether it reaches the actual end; final query verification must reject apparent numeric matches at an unknown non-terminal boundary and de-duplicate overlap spans.

Search units distinguish saved current/history versions, skip the duplicate current historical snapshot, retain canonical original inventory locations (including legacy PDF bottom-left conversion), and disclose absent/incomplete source text. Legacy field/region text remains searchable but is not given guessed original coordinates. Translation-to-original mapping, encrypted derived index persistence/postings, search/open APIs, rebuild/progress UI, save/delete/restore integration and archive measurements are still pending. These helpers alone are not the user-facing P10 feature.

Evidence: 26 focused checks across the existing JobStore suite and new reader/material/Unicode cases passed; two chunk/version-provenance checks passed separately. Seven existing workspace backup/restore/encryption checks passed, including streaming legacy large-text restoration with fingerprint preservation. Logs: ignored `outputs/workflow-P10-material.log` and `outputs/workflow-P10-reader-compatibility.log`. No UI/provider operation, version bump, package or release was introduced. P10 and all integrated release gates remain open.
