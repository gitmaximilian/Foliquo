# Review of Foliquo 0.14.1 — November 2026

This review covers the translation workflow, technical implementation and UI/UX of the 0.14.1 source. It records what was checked, what was fixed, and what still needs a decision. It does not claim linguistic accuracy, certification fitness or measured quality improvements.

## Method and evidence boundary

- Baseline: `main` at `e63f93e` (0.14.1). `npm ci --ignore-scripts`, then `npm test`: 478 tests, 477 passed, 1 skipped, 0 failed, about 4 minutes on Node.js 22.23.
- Code reading of `server.mjs`, the provider adapters, the translation policy, and the frontend translation and rendering paths.
- `npm audit` (production and development dependencies): 0 known vulnerabilities.
- A Playwright walkthrough in Chromium with a fixture provider and a fictional PDF: studio, library, Foli, Learn style, guide, queue, clarification, finished job and review. It covered English, German and Arabic (RTL), with desktop light, desktop dark and mobile (iPhone 13). It ran axe-core (WCAG 2.0/2.1 A and AA rules) on each view and scanned visible text and `aria-label`, `title` and `placeholder` attributes for German leftovers in the English and Arabic interfaces.
- No live provider requests were made. Firefox and WebKit were not run, and no screen-reader session was performed. Queue concurrency was reviewed only at the level of the code paths named below.

Findings are marked **Verified** (reproduced or shown by a test or screenshot) or **Suspected** (follows from code reading, not reproduced).

## Fixed in this review (small, low-risk)

| ID | Area | Finding | Evidence | Change |
| --- | --- | --- | --- | --- |
| F1 | Security | **Verified.** Several state-changing routes run before the general origin/CSRF gate in `server.mjs`: `POST /api/import-batches/preview`, `POST /api/import-batches`, the batch `continue`/`pause`/`resume` actions, `POST /api/usage/consent-once`, the dossier create/entity/fact/document routes and two dossier `DELETE` routes. They relied only on the `SameSite=Lax` cookie. Pages served from another port on `127.0.0.1` are same-site and receive that cookie. | New `tests/csrf-gate.test.mjs` fails on the baseline and passes after the change. | The existing origin and token check now applies to every non-GET/HEAD request directly after session lookup. All frontend, desktop and script callers already send both headers. |
| F2 | UI, i18n | **Verified.** In English and Arabic the clarification dialog showed the German placeholder "Deine Antwort …" and the button "Antwort senden", and the toast "Antworten werden benötigt." stayed German. | Screenshots `en-desktop-light-clarify` before and after the change. New `tests/clarification-copy.test.mjs`. | Added English and Arabic dictionary entries. |
| F3 | Accessibility | **Verified.** Review confirmation checkboxes announced the German check label, e.g. "Reviewed against the original: Vollständigkeit aller Seiten …". | Rendered `aria-label` scan, regression test. | The label is passed through the interface dictionary. |
| F4 | Accessibility | **Verified.** The toast action button contrast was 4.25:1, below WCAG AA 4.5:1 (axe `color-contrast`, serious). | axe, regression test. | The background changed from `#2e79e8` to `#4a8bf0`, giving 5.29:1 with the existing dark text. After the fix, axe reported no violations on the walked English and Arabic desktop views. |

## Fixed after owner decisions

The owner decided that clarification questions follow the interface language and that LibreOffice stays the PDF/Word layout engine.
