# Review of Foliquo 0.14.1 — November 2026

This review covers the translation workflow, technical implementation and UI/UX of the 0.14.1 source. It records what was checked, what was fixed, and what still needs a decision. It does not claim linguistic accuracy, certification fitness or measured quality improvements.

## Method and evidence boundary

- Baseline: `main` at `e63f93e` (0.14.1). `npm ci --ignore-scripts`, then `npm test`: 478 tests, 477 passed, 1 skipped, 0 failed, about 4 minutes on Node.js 22.23.
- Code reading of `server.mjs`, the provider adapters, the translation policy, and the frontend translation and rendering paths.
- `npm audit` (production and development dependencies): 0 known vulnerabilities.
- A Playwright walkthrough in Chromium with a fixture provider and a fictional PDF: studio, library, Foli, Learn style, guide, queue, clarification, finished job and review. It covered English, German and Arabic (RTL), with desktop light, desktop dark and mobile (iPhone 13). It ran axe-core (WCAG 2.0/2.1 A and AA rules) on each view and scanned visible text and `aria-label`, `title` and `placeholder` attributes for German leftovers in the English and Arabic interfaces.
- No live provider requests were made. Firefox and WebKit were not run, and no screen-reader session was performed. Queue concurrency was reviewed only at the level of the code paths named below.

Findings are marked **Verified** (reproduced or shown by a test or screenshot) or **Suspected** (follows from code reading, not reproduced).

## Fixed in this review (small, low-risk)

| ID | Area | Finding | Evidence | Change |
| --- | --- | --- | --- | --- |
| F1 | Security | **Verified.** Several state-changing routes run before the general origin/CSRF gate in `server.mjs`: `POST /api/import-batches/preview`, `POST /api/import-batches`, the batch `continue`/`pause`/`resume` actions, `POST /api/usage/consent-once`, the dossier create/entity/fact/document routes and two dossier `DELETE` routes. They relied only on the `SameSite=Lax` cookie. Pages served from another port on `127.0.0.1` are same-site and receive that cookie. | New `tests/csrf-gate.test.mjs` fails on the baseline and passes after the change. | The existing origin and token check now applies to every non-GET/HEAD request directly after session lookup. All frontend, desktop and script callers already send both headers. |
| F2 | UI, i18n | **Verified.** In English and Arabic the clarification dialog showed the German placeholder "Deine Antwort …" and the button "Antwort senden", and the toast "Antworten werden benötigt." stayed German. | Screenshots `en-desktop-light-clarify` before and after the change. New `tests/clarification-copy.test.mjs`. | Added English and Arabic dictionary entries. |
| F3 | Accessibility | **Verified.** Review confirmation checkboxes announced the German check label, e.g. "Reviewed against the original: Vollständigkeit aller Seiten …". | Rendered `aria-label` scan, regression test. | The label is passed through the interface dictionary. |
| F4 | Accessibility | **Verified.** The toast action button contrast was 4.25:1, below WCAG AA 4.5:1 (axe `color-contrast`, serious). | axe, regression test. | The background changed from `#2e79e8` to `#4a8bf0`, giving 5.29:1 with the existing dark text. After the fix, axe reported no violations on the walked English and Arabic desktop views. |

## Open findings and proposals

Effort: S (hours), M (a focused change across a few files with tests), L (multi-step refactor). Each item needs an owner decision before work starts.

| ID | Area | Finding | Evidence | Effort / risk | Proposal |
| --- | --- | --- | --- | --- | --- |
| W1 | Workflow | **Verified in code.** Notations are German regardless of the target language. `lib/form-fields.mjs:6` forces `[Unterschrift: unleserlich]` and `[Handschriftlich: …]`. The prompt in `lib/translation-policy.mjs:9-10` only names German notations and the "Stempel:" heading. English or Arabic target documents can therefore contain German bracket notes. | Code lines named. | M / medium. Several parsers match the German tokens (`translation-policy.mjs:74`, `:89`; `documents.mjs:115`). | Introduce a per-target-language notation table (`de`, `en`, `ar`, falling back to the target language) used by the prompt, the form-field mapping and the parsers. Add fixtures for each target language. |
| W2 | Workflow | **Verified in code.** Model-authored clarification questions are always German (`translation-policy.mjs:9`, "stelle gezielte Fragen in deutscher Sprache"). App-authored questions are localized by `dist/question-copy.js`; model questions are not. | Code line named. | M / medium. It changes prompt behavior and needs fixture updates. | Ask in the interface language and keep stable question IDs. Alternatively, keep German and show a short note in English and Arabic interfaces. |
| W3 | Workflow, UX | **Verified.** The clarification dialog has two submit paths: "Send answer" on each question and "Send answers & continue" below. With a single question it is unclear which one to use. | Screenshot `en-desktop-light-clarify`. | S–M / low. | Keep one primary action. Change the per-question action to "Save answer" (draft) or hide it when only one question is open. |
| W4 | Workflow, UX | **Verified.** On the review page, "PDF + Word" is the visually primary action and sits above the checklist while six checks are still open. The final-download acknowledgement still protects the review boundary. | Screenshot `en-desktop-light-review`. | S–M / low, but it touches the review boundary. | Show the open-check count beside the download actions and make "Next open item" the primary action until the version is marked reviewed. Downloads remain available. |
| U1 | UX, mobile | **Verified.** On a phone-sized viewport the navigation fills about the first third of the screen; the upload control is below the fold. | Screenshot `en-mobile-studio`. | M / low. | Use a compact horizontal tab bar or a bottom bar on narrow viewports. |
| U2 | UX | **Verified.** The clarification "Add a clearer image" area uses the browser's unstyled file input, whose "Choose Files" label follows the browser language rather than the interface language, and larger body text than the rest of the dialog. | Screenshot `en-desktop-light-clarify`. | S / low. | Use the same styled file button as the main upload area and the dialog's body text size. |
| U3 | UX | **Verified.** In the studio, "Rules · 0 effective" sits at the right end of an otherwise empty full-width strip, and the greeting floats in the middle of the header. | Screenshot `en-desktop-light-studio`. | S / low. | Align the rules summary with the options column or merge it into the options card. Align the greeting with the page title. |
| T1 | Security | **Verified in code.** The main application has no Content-Security-Policy. A CSP is feasible: `dist/index.html` has no inline scripts or inline event handlers, the frontend uses no `eval`/`new Function`, and `innerHTML` is used only with static markup. | `grep` over `dist/`. | M / medium. PDF.js, the Tesseract workers and WebAssembly must be verified in all three browsers. | Add `default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; worker-src 'self' blob:; img-src 'self' data: blob:; style-src 'self' 'unsafe-inline'; connect-src 'self'; object-src 'none'; base-uri 'none'; frame-ancestors 'none'`. Then run the browser suites and the demo. |
| T2 | Maintainability | **Verified.** `server.mjs` is 183 KB. Routing for about 100 endpoints lives in one request handler with very long lines, and correctness depends on route order (the cause of F1). | File size and structure. | L / medium. | No rewrite. Extract route groups incrementally into `lib/*-api.mjs` modules, following the existing `rule-api` and `foli-api` pattern, one group per change with unchanged behavior and existing tests. |
| T3 | Providers | **Suspected.** When the Anthropic model catalog reports no output limit, requests fall back to `max_tokens` 4096 (`lib/providers.mjs:112`, `:128`). Truncation is detected and reported (`:82`), so no content is silently lost, but larger documents can fail and need to be split. | Code lines named. | S / low. | Use a documented higher default for current models. Keep the explicit truncation error. |
| T4 | Test infrastructure | **Verified.** The browser specs (`npm run test:browser`) use `@playwright/test` 1.64.1. They need the matching Playwright browsers, which were not available in this environment, so they were not run here. They are not part of the mandatory check list. | Environment check. | S / low. | Keep them in CI; run them locally before UI releases. |

## Recommended order (top 10)

1. W1, so English and Arabic target documents no longer contain German notations.
2. W4: make review progress visible before download.
3. W3: one clear action when answering clarifications.
4. T1: a CSP as defense in depth.
5. W2: question language.
6. U1: mobile navigation.
7. U2 and U3: visual consistency fixes.
8. T3: Claude output limit default.
9. T2: incremental extraction of route groups from `server.mjs`.
10. T4: confirm the browser suites in CI for every UI change.

## Not changed

Excluded scope remains excluded: U8, G1, G10, WinGet, operating-system signing and notarization, and Cloudflare deployment. No release, tag, version number or published asset was changed.
